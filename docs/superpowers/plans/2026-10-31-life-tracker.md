# Life Tracker Implementation Plan

> **Status: executed 2026-10-31** (all 11 tasks, plus a review fix pass). Kept as a historical record; later changes live in the spec and git history. Do not re-execute.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a single-user, local web app for logging fitness, reading, habits, mood, and learning, with streaks, goal progress, and charts.

**Architecture:** One npm package. A Hono server (`server/`) owns a SQLite file through Drizzle and does all calculations in pure functions under `server/stats/`. A Vite + React front end (`web/`) talks to it over `/api/*` (proxied by Vite in dev). Shared types and Zod schemas live in `shared/`.

**Tech Stack:** TypeScript, Node.js, Hono (`hono`, `@hono/node-server`, `@hono/zod-validator`), Zod, Drizzle ORM + `better-sqlite3` + `drizzle-kit`, React + `react-router-dom`, Recharts, Vite, Vitest, `tsx`, `concurrently`.

**Spec:** `docs/superpowers/specs/2026-10-31-life-tracker-design.md`

## Global Constraints

- Dates are `'YYYY-MM-DD'` strings in local time everywhere. Never store or compare entry dates as JS `Date` objects (`Date` is only used inside `todayLocal()`).
- One entry per `(tracker_id, date)`; one reading_log row per `(book_id, date)`. Saving again overwrites.
- Tracker kinds: `'check' | 'quantity' | 'rating'`. `check` value = 1; `rating` integer 1–5; `quantity` ≥ 0.
- `page_reached` between 0 and the book's `total_pages`.
- Weeks are Monday–Sunday; months are calendar months.
- Goals store rules only; all progress is calculated. Archived trackers' entries still count.
- Every API request body is validated with Zod; errors return JSON `{ error: string }` with status 400 (invalid), 404 (missing), or 409 (conflict).
- `tracker.db` is personal data: listed in `.gitignore`, never committed.
- Server listens on port 3000; Vite dev server on 5173 proxies `/api` to it.
- **Learning mode:** steps marked **👤 USER WRITES** are left for the user to implement. The implementer creates the file, signature, and doc comment, writes the tests, stubs the body with `throw new Error("TODO: user implements")`, then stops and asks the user to fill it in before continuing.

## Review Focus

1. **Correcting a page number downward** (logged 150 by mistake, then 120) must not produce negative "pages read." Pinned in Task 4.
2. **Archived trackers** must still count toward area active days and goal progress. Pinned in Task 8.
3. **A checklist goal with zero items** must report `0 / 0` with percent 0, never `NaN`. Pinned in Task 5.
4. **Deleting an area that still has trackers** must be refused (409), not leave orphaned trackers. Pinned in Task 6.
5. **Changing a tracker's `kind` after it has entries** would silently reinterpret old values (a `90`-minute entry becoming an invalid rating), so `kind` is immutable after creation. Pinned in Task 6.
