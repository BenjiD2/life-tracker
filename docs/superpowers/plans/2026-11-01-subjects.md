# Subjects and Estimated Time Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trackers get an optional subject tag and minutes-per-unit, so the dashboard can show per-subject sections with one chart per unit plus estimated total time.

**Architecture:** Two nullable columns on `trackers`. Shared pure helpers (`shared/subjects.ts`) define subject grouping and the minutes rule, and are used by both server and web. A pure stats function returns minutes per tracker per bucket on the dashboard payload. The web groups and charts from that payload plus the tracker list.

**Tech Stack:** Hono, Drizzle/SQLite (drizzle-kit migrations), Zod, React 19, Recharts, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-01-subjects-design.md` (and CLAUDE.md for repo rules).

## Global Constraints

- Branch `subjects`. Commit per task; end commit messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push or merge.
- `tracker.db` is live. Run `npm run backup` before generating the migration. Never write test data to it. Verify UI only on ports 3101/5199 against a scratch DB, after checking `lsof -nP -iTCP:3000 -iTCP:5173 -sTCP:LISTEN`.
- Minute units: `minutes`, `minute`, `min`, `mins` (trimmed, case-insensitive).
- Subject grouping: trimmed, case-insensitive. Empty means no subject. The label is the spelling on the lowest-id tracker in the group. Grouping is per area.
- `minutesPerUnit`: positive and finite, or null. Non-null on a non-quantity tracker returns 400.
- Every tracker with `minutesPerUnit` set is "converted" and is shown as estimated (lighter fill, "(est.)" in the legend).
- Errors are `{ error }` JSON. Dates are `DateStr`. Calculation lives in pure functions (`server/stats/`, `shared/`).
- Run `npm test` and `npm run typecheck` at the end of every task.

## Review Focus

1. **Subject spelled inconsistently** ("chinese", " Chinese ") → one section. Pinned in Task 1 (`groupBySubject` test).
2. **A tracker's unit renamed to `minutes` while `minutesPerUnit` = 40** → the multiplier still applies, and Manage still shows the field so it can be cleared. Pinned in Task 1 (`minutesFactor` test). The UI rule is in Task 4.
3. **Clearing min-each** (PATCH `minutesPerUnit: null`, or `subject: ""`) → stored as null and the tracker drops out of estimates. Pinned in Task 2.
4. **The UI sends `minutesPerUnit: null` for a check or rating tracker** → accepted (only non-null is refused). Pinned in Task 2.
5. **Archived trackers with history in the range** keep showing in subject sections and estimates, like today's totals. The current filter rule (non-archived, or non-zero in the window) is reused in Task 6 and checked during manual verification.
